# Inside Chat fork of Element Web

This is the Element Web build used by **Inside Chat**, the internal messenger of Inside Estate
(Matrix server `lobby.inside.estate`). Deployment, configuration and the visual skin live in a
separate repository, `balakirev/inside-chat`; this repository holds only changes to the app itself.

## Branches and tags

| Ref                      | Meaning                                                        |
| ------------------------ | -------------------------------------------------------------- |
| `inside/main`            | upstream release tag (see `.inside-base`) + our commits on top |
| `inside-v<upstream>-<n>` | image that production pins to, e.g. `inside-v1.12.32-1`        |

Every Inside change is a separate, small commit on `inside/main`, so it can be re-applied on top of
the next upstream release with `git rebase --onto <new-tag> <old-tag> inside/main`.

## What we change and why

| Change                                 | Why                                                                                                                                                                                                                                                                                                                                                                       |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Caption field in the upload dialog     | Users expect to send a photo with a caption in one message, as in other messengers. Uses Matrix media captions (`body` = caption, `filename` = file name), which Element and Element X already render. The "discard caption?" question is drawn inside the dialog: `Modal` shows only the topmost dialog, so a second dialog would unmount this one and lose the caption. |
| Media in the upload dialog             | An image or a video is shown on its own with the name and size as one quiet line under it, without the file-type tile (kept for other files). A PDF shows its first page there once drawn (`mx_UploadConfirmDialog_inside_document`), the file tile until then. The caption field takes the focus however the dialog opened (attach button, drag and drop, paste) and has a stable class `mx_UploadConfirmDialog_inside_caption` for the skin. |
| Files being sent in the timeline       | While a file uploads, the end of the room timeline shows it as an own bubble, as in Telegram: a dimmed preview of the image or video (a file bubble for other files, with the first page of a PDF under the ring and "12 % · 12.3 of 42.5 MB") with a turning circular progress (counting the thumbnail of images, videos and PDFs, which goes up next to the file rather than before it; a thumbnail that fails to upload is left out instead of failing the send), a cancel button and "12.3 of 42.5 MB", and the caption under it (`InsidePendingUploads`). The event takes the bubble's place once it is in the timeline. A failed upload stays there with "Retry" and "Delete" instead of an error dialog; when the file was uploaded and only the message failed to send, Element's unsent message (red mark, "resend" in the room status bar) takes over and the bubble goes, so the failure is shown once. Replaces the upload bar of the room; threads keep the bar and the dialog. |
| Room list items like other messengers  | Time of the latest message on the right, the sender of group messages on its own line, sent/read ticks for the user's own latest message, a muted icon, two-line previews.                                                                                                                                                                                                |
| Quick reactions above the context menu | One-tap emoji row with a button for the full picker, as in other messengers; replaces the "React" menu item.                                                                                                                                                                                                                                                              |
| Message menu on media                  | As in Telegram, a right-click anywhere on a photo, video, file tile, audio or voice message or sticker opens the message menu (quick reactions, reply, forward, delete…) instead of the browser's "Save image as" / "Open link" menu: Element left everything inside a link or on an `<img>` to the browser, and media bodies are links to the lightbox or the download (`EventTile.isOnMediaBody`). Links and images in message text and in captions, and the timestamp, keep the native menu; clicks still open the lightbox, the viewer or the download. |
| Reactions inside the bubble            | In the bubble layout reactions sit under the message text with the time on their right.                                                                                                                                                                                                                                                                                   |
| Voice message button                   | While the composer is empty, the round button in place of "send" records a voice message, as in other messengers. Element only offered it in the "more options" menu. |
| Editing in the composer                | Editing a message opens it in the main composer under an "Editing" bar, with a round save button in place of "send", as in other messengers; the bubble stays as it is. Element edited inside the bubble. The send composer unmounts meanwhile and gets its draft back from local storage. Not with the rich text editor (labs), which still edits in the timeline. |
| Bar under the room list                | Contacts (start a chat), Chats (all chats) and the user's avatar with Element's user menu, moved from the top of the space panel — the bottom tab bar of other messengers. |
| Media retry after a 401                | With MAS access tokens expire; the service worker used a stale stored token and avatars stayed broken. It now asks the tab to refresh the token and retries once. |
| "Open here" on the other-tab screen    | The tab that lost the session to another tab gets a button to take it back in one click instead of only "close this tab". |
| Notifications in the context menu       | Right-click on a room offers the notification options (mute and others), as Mute in other messengers; the Inside skin hides the hover buttons. |
| Folders in the space panel             | Under "All chats": Groups, Colleagues, Clients, VIP, Favourites — room list filters, as folders of other messengers. Colleagues/clients: the other side of a DM is on our server, or on another server / a bridged network. |
| Narrow windows and phones             | As Telegram Web K, the layout follows the window width (`utils/InsideLayout.ts`: up to 600 px one column, up to 925 px no space panel; the Inside skin uses the same numbers). In narrow windows the room list has a menu button left of the search (the user, contacts, favourites, settings, night mode), the space panel folders as tabs with their number of unread chats (`InsideFolderTabs`, counted by `stores/room-list-v3/InsideFolderUnread.ts`, shared with the space panel), and a round pencil button with new group / new chat (`InsideComposeFab`) instead of the header and the bar under the list. |
| One column on a phone                 | Up to 600 px the app starts on the room list instead of the last room; the room header gets a back arrow with the number of unread chats (`RoomHeader/InsideBackButton.tsx`). Back goes through the browser history when the room was opened from the list, so the system Back and the arrow agree (`utils/InsideMobileNavigation.ts`, which also waits for the skin's slide-out unless reduced motion is asked for). A room opened from the list on a phone hides its remembered right panel, which would cover it. The skin does the columns and the animations. |
| Long press on iOS                      | Safari on iOS sends no `contextmenu` for a long press, so the message menu and the room options could not be opened on an iPhone. A still finger for 500 ms on a message or a room list item now sends it (`utils/InsideLongPress.ts`); the click that ends the press is swallowed. Chrome on Android does it by itself. |
| Composer buttons in phone-wide rooms   | Element called a room under 500 px "narrow" and moved the attach and voice buttons into the composer's menu; the threshold is 300 px, so a phone keeps them around the composer, as Telegram (`RoomView`, `INSIDE_NARROW_ROOM_WIDTH`). |
| VIP in the room context menu           | A private room tag (`u.inside.vip`) for the VIP folder, independent of the room list sections. |
| Own avatar opens the settings          | The last tab of the bar under the room list is the user's avatar and opens the settings, which show the profile (avatar, name, ID) above their tabs — the Settings screen of other messengers. |
| No verify-this-device prompts         | With `inside_hide_device_verification` in config.json, the "verify this device" toast is not shown, and a fresh login skips the full-screen verify/key-setup views (encryption is off server-wide; remove the key if E2EE comes back). |
| Robust media auth in the service worker | The worker waits up to 5 s for the tab's token, and on a 401 asks the tab to refresh once (shared by all requests of a burst) and retries with auth — no broken avatars right after start. |
| Dust when deleting a message          | After the delete confirmation the message turns to dust as in Telegram's "Thanos snap" (`utils/DustEffect.ts`): a copy of the bubble is painted from its real pixels (backgrounds, text, photos, file tiles) and cut into 2 px particles with their own colours; a wave starts from the sender's side (own bubbles from the right, others' from the left), the particles drift up and away from it and fade, about 1 s in all. The row's height closes smoothly at the same time to what the timeline shows there ("Message deleted", or nothing: a spacer takes the removed tile's place), so nothing jumps. One shared WebGL canvas and one animation frame loop for every running effect (Canvas2D with fewer particles if WebGL is missing); the canvas, GL buffers and context are released when the last effect ends, also when the room is switched or the thread closed mid-way (the effect ends at once), and a timer puts the DOM back if no frame runs (background tab). Several messages at once cascade top to bottom; a tile already going is left alone. With reduced motion the bubble fades out and the space closes, no particles. Works for text, photos, files, own and others' messages and in threads (a thread root in two places goes in both). Classes `mx_InsideDustOverlay`, `mx_InsideDustCanvas`, `mx_InsideDustSpacer`. |
| Favicon badge in the brand red        | The unread counter drawn over the tab icon uses the Lobby signal red `#C8102E` instead of Element's `#d00`. |
| Search and More in the room header    | The right side of the room header is the Lobby button capsule: search, threads, room info, more. Search opens the room's message search as Ctrl+F does; More opens the room list item's options menu below the button (`RoomHeader/InsideHeaderButtons.tsx`). |
| Room info as in Telegram             | Under the profile of the room info card a row of tiles: call (the header's voice call, hidden where the header hides it), mute / unmute (the room list's mute), search, more (the room options menu). At its end the Media / Files / Links tabs: a grid of images and videos, lists of files and of messages with links, loaded when a tab is opened and paged on scroll from filtered timelines as in FilePanel (`right_panel/InsideRoomSummary.tsx`). |
| Muted text follows the theme       | The legacy `$muted-fg-color` (blue-grey `#61708b`, used by the upload bar, home page and others) now points at `--cpd-color-text-secondary`, so skins recolour it with the rest of the theme. |
| PDF thumbnail frame in the viewport | The hidden frame that draws page 1 of a PDF sits inside the viewport (invisible, behind everything): Chromium does not paint an off-screen cross-origin frame, so pdf.js never finished. |
| Lazy PDF previews up to 20 MB    | Old PDFs without a sent thumbnail get page 1 drawn when the tile shows, now up to 20 MB (was 5 MB) — the same limit as the media cache, so opening the file after that is instant. |
| Threads                                | The bar under a message with replies shows a stack of up to three reply participants' avatars and always the count with the word ("3 replies"), also in the thread list; the thread panel header has "<room> · N replies" under its title; the empty thread composer offers the voice message button too (Element hid it in the narrow thread panel), and voice messages name their thread like text ones; the thread composer always says "Reply in thread" (Element only did while replying to a message). |
| Escape closes the right panel          | As in Telegram, Escape closes the open thread, room or user info panel (`RoomView.closeRightPanelOnEscape`) and puts focus back into the composer if it was in the panel. Dialogs, menus, autocomplete and cancelling a reply or an edit take the press first; a text field with text and the room search keep it. |
| Avatar at the last bubble of a series  | In the bubble layout the sender avatar sits at the last message of a series (`mx_EventTile_inside_lastInSeries`), the name above the first one, as in Telegram. |
| Names without the Matrix ID           | Same-named members (one person with two accounts) no longer get " (@user:server)" in event texts (also the room avatar change, membership summaries, calls, emotes), notification titles, room list previews and the timeline sender; kept for names that look like a Matrix ID or contain direction marks, and in the member list and user info (`utils/event/getSenderName.ts`). |
| Online members in the room header      | "6 members · 2 online": the number of joined members whose presence is online, next to the member count (`mx_RoomHeader_inside_online`). |
| Pin for favourite rooms                | A favourite room without unread messages shows a pin where the unread badge would be (`mx_RoomListItemView_inside_pin`). |
| Counter on muted rooms                 | A muted room keeps a grey counter of its unread messages in the room list (`mx_RoomListItemView_inside_muted`), counted on the client because servers do not count them; folders and the favicon still leave it out. |
| File sizes in the app language         | "8,6 МБ", "861 Б" instead of "8.63 MB", "861 Bytes": `formatBytes` (shared components) uses the units of `Intl.NumberFormat` in the current language, one decimal place, and `fileSize` (file tiles, upload dialog and bar) uses it; English writes "861 bytes", "8.6 MB", "1 kB". |
| Document viewer on by default          | The PDF (and Markdown) viewer of the right panel, Element's "document previews" lab (`feature_pdf_viewer`), is on by default, so a PDF opens in the app instead of downloading; `features` in config.json can still turn it off. |
| First page of a PDF as its thumbnail   | A PDF is sent with a picture of its first page (JPEG, 320 px on the long side) as the standard `info.thumbnail_url` / `thumbnail_file` + `thumbnail_info` of the `m.file` event, as Telegram does. pdf.js draws it in the PDF viewer's sandboxed usercontent iframe (new `thumbnail` message), hidden and one at a time, up to 50 MB and 20 s; a PDF that is protected, broken or too large is sent without one (`utils/pdfThumbnail.ts`). |
| Photos compressed before sending      | As Telegram's "send as photo": a JPEG, PNG, WebP or HEIC photo longer than 2560 px or larger than 1.5 MB is sent with its long side at 2560 px, as JPEG at quality 0.85 (WebP, or PNG where the browser cannot encode WebP, if it has transparency), upright by its EXIF orientation and without EXIF (camera, GPS); HEIC is always converted, since only Safari shows it. Done in a worker with an OffscreenCanvas where there is one (`utils/photoCompression.ts`, `utils/compressPhoto.ts`, `workers/photoCompression.worker.ts`); the event's `w`/`h`/`size`/`mimetype`/blurhash and the name (".jpg") describe the compressed file. GIFs, animated WebP/PNG, files under another extension and anything that fails go as they are. The upload dialog has a "No compression" switch (`mx_UploadConfirmDialog_inside_original`), kept on the device (`Inside.uploadOriginals`, off by default) and applied to "Upload all"; the pending bubble says "Compressing…" meanwhile. |
| Videos compressed before sending      | As Telegram: where the browser has WebCodecs, a video over 20 MB or taller than 1080p is transcoded to H.264 of at most 1080p (720p over 100 MB) at 5 Mbps (4 Mbps at 720p), AAC audio copied (other audio re-encoded to AAC), into an MP4 with `moov` at the start, so it plays before it has fully downloaded, and without the tags (phones write the place). Mediabunny (MPL-2.0, loaded only then) reads and writes the file (`utils/compressVideo.ts`). The pending bubble shows "Compressing… 45 %" on the ring and can cancel it. The original goes if the result is not 20 % smaller, the codecs are missing, the encoder stands still for 10 s, the work takes longer than 30 s plus the video's length (10 min at most), or anything fails; "No compression" applies too. The first frame for the poster is read through an object URL instead of a data URL of the whole file. |
| Event first, file after (MSC2246)     | Files of 2 MB and more go as Telegram sends them: the client reserves an mxc URI (`POST /_matrix/media/v1/create`), sends the event with it, the blurhash, `w`/`h` and the thumbnail (uploaded first, it is small) at once, and uploads the file to that URI after it (`PUT /_matrix/media/v3/upload/{server}/{id}`, `utils/asyncMediaUpload.ts`). Receivers see the message right away; until the file is up Synapse holds downloads of it for 20 s (60 s with `timeout_ms`) and then answers 504 `M_NOT_YET_UPLOADED`. The sender's event stays hidden behind its pending bubble until the file is up (`ContentMessages.isMediaPendingFor`, `MessagePanel.shouldShowEvent`) and then shows its local bytes; cancel aborts the upload and redacts the event; a failed upload keeps the bubble, whose "Retry" puts the same file to the same URI and "Delete" redacts the event. The next file of a batch follows once this one's event is out. Only where the server speaks Matrix 1.7, the room is not encrypted and the server grants a URI (it allows five pending ones); otherwise the classic upload. Setting `Inside.asyncMediaUpload` (device or `setting_defaults` in config.json), on by default. |
| Files as document tiles               | In the room, thread and search timelines a file is a Telegram-like tile: a rounded 68 px picture on the left (the thumbnail sent with it, or a document icon with the type), the name in one line cut in the middle and "8,6 МБ · PDF" under it. The whole tile opens the file in the Quick Look window if it can show it (PDF, Markdown, text) or downloads it; the button on the right downloads. A PDF up to 5 MB sent without a thumbnail gets its first page drawn once the tile is on screen, cached for the session (`InsideDocumentTile.tsx`; classes `mx_MFileBody_inside_doc`, `_open`, `_thumb`, `_thumb_picture`, `_icon`, `_name`, `_meta`, `_download`). The file panel keeps Element's tile. |
| PDF in a Quick Look window             | A PDF, a Markdown file (`text/markdown`, `.md`) or a plain text file (`text/plain`, `.txt`/`.log` without a mimetype) never opens in the right panel: the tile (click, Enter, Space), the Files tab of room info, the file panel and the message menu open it in a window over the app, as Space in the macOS Finder (`elements/InsideQuickLook.tsx`, opened by `openDocumentViewer`; `RightPanelStore` turns such a card into the window too). The pages are drawn by Element's sandboxed pdf.js usercontent frame and scroll inside the window; the header has the name, "стр. 3 из 12 · 8,6 МБ", zoom −/+, "Скачать" (the tile's download, same name) and ×. Escape (also in the frame, which hands it over with a new `dismiss` message), the backdrop and × close it without closing the right panel, and the focus goes back to the tile; ↑/↓, Page Up/Down, Space, Home/End scroll (new `scroll` message), ⌘/Ctrl +/− zoom; focus is trapped. Markdown is rendered and sanitized by Element's Markdown viewer (links to rooms, users and messages are followed in the app and close the window), plain text is shown as it is in a monospace `<pre>` (`InsidePlainTextViewer.tsx`, also the right panel viewer for text, up to 2 MB like Markdown); both scroll inside the window with the same keys, the header has the name, the size, "Скачать" and × (no page count or zoom); classes `mx_InsideQuickLook_document`, `mx_InsidePlainTextViewer`. Backdrop rgba(0,0,0,.45) with a blur, scale .96→1 and fade in 160 ms, none with reduced motion. Classes `mx_InsideQuickLook`, `_backdrop`, `_window`, `_header`, `_title`, `_meta`, `_download`, `_close`, `_body`. Images keep the lightbox, other files download. |
| Media cache in the service worker      | Thumbnails, and originals up to 20 MB, are kept in Cache Storage (`inside-media-v1`, up to 300 MB, least recently used out) keyed by the v3 media URL with sorted parameters, and served from there first: content behind an mxc URI never changes. Only complete 200 answers are kept; a video or download is kept only if the page read all of it, so a video fetching only its metadata does not pull the rest. Two requests for the same file share one download. Cleared with the rest of the session storage (`clearStorage`). `serviceworker/mediaCache.ts`. |
| Video ranges in the service worker      | Synapse ignores `Range` and sends the whole file with 200. The worker passes `Range` on, and turns a 200 into the 206 that media elements (Safari above all) expect, skipping the bytes before the range and stopping the download once the range is complete; a cached video is cut from the cache, so it seeks at once. Seeking in a large video that is not cached still downloads from the start: real ranges need the server. |
| Media still being uploaded              | For an event sent before its file finished uploading (MSC2246) Synapse answers 504 `M_NOT_YET_UPLOADED`. The worker asks again with `timeout_ms=60000` for up to 4 minutes (and once or twice more for a thumbnail that is a 404 just after the upload, before Synapse made it), so the picture appears by itself. If it still fails, the image tile asks the server (header `X-Inside-No-Wait`) and, while the file is pending, keeps its blurhash with a spinner and loads again with backoff (`?inside_retry=N`, dropped by the worker) instead of showing a broken image. |
| Thumbnail size for the bubble            | Our Synapse prepares thumbnails at upload (`dynamic_thumbnails: false`, sizes 320×240, 640×480, 800×600). An image asks for the smallest of them that is sharp in its bubble on this screen (320×240 for a normal bubble at 1×, 640×480 at 2×) instead of always 800×600, and on a high-DPI screen the original only when no size is sharp enough and the original is under 1 MB (`utils/media/serverThumbnail.ts`, `Media.getServerThumbnailOfSourceHttp`). |
| Blurhash at once                        | An image with a blurhash shows it from the start, with a small spinner over it after a second (`placeholderBusy` of `ImageBodyView`); Element showed it only after 150 ms, and nothing before. |
| Thumbnails loaded in advance            | After the initial sync and after reconnecting, the thumbnails of the latest 4 images, video posters and file pictures of the 8 rooms with the latest activity (the top of the room list, other than the open one) are loaded at idle time, two at a time, into the media cache; so is a new media message in a room other than the open one. Not with "low bandwidth" or Save-Data, not for encrypted media or media the user chose not to preview (`utils/media/InsideMediaPrefetcher.ts`). |
| Round video messages                  | As in Telegram Desktop, the round button of the empty composer records voice or round video («кружки»): a tap (under 250 ms) swaps the mic and the camera with a turn-and-fade animation and the mode is kept on the device (`mx_inside_record_mode` in local storage); press and hold records in the current mode, release sends, sliding up 60 px locks (a voice message then goes on in Element's recording UI with stop, delete and send, as before; a locked round video turns the button into "send" and offers a delete button), sliding left 110 px or Escape cancels, Enter or Space start a locked recording; mouse and touch (`InsideRecordButton.tsx`, `utils/recordGesture.ts`). A round video shows the front camera live in a 280 px circle over the chat, with a white 60 s progress ring on its edge, a timer and "slide left to cancel" (`mx_InsideRoundRecorder`). It is the centre square of the camera, mirrored as the user sees themselves, drawn at 384×384 on a canvas and recorded with the microphone by MediaRecorder: MP4 H.264/AAC where the browser can (Chrome, Safari), WebM VP9/VP8+Opus otherwise, 1 Mbit/s video, 64 kbit/s audio, 30 fps; it stops and sends by itself at 60 s, and under 1 s is thrown away (`utils/RoundVideoRecorder.ts`). A refused permission, a missing or busy camera or a browser without MediaRecorder get a dialog in plain words. It is sent through the usual upload path (MSC2246 for 2 MB and more; its pending bubble is the same 260 px circle with the first frame dimmed, the progress ring on its edge and cancel in the middle, `mx_InsidePendingUpload_roundVideo`), not compressed again, as `m.video` with `info` `w`/`h`/`duration`/`size`/`mimetype`, the first frame as the thumbnail with its blurhash, `body` `video_note.mp4` (`.webm`), and the flag **`"estate.inside.lobby.video_note": true`** in the content, as the Lobby contract defines it (`utils/sendRoundVideo.ts`; `sendContentToRoom` takes `extraContent` and `info` for it). Other clients show a normal video. As the contract says, a client draws it as a circle only with the flag, a square picture (`info.w == info.h`) and `info.duration` ≤ 60000 ms, otherwise as an ordinary video (`isRoundVideoContent`). In the room, thread and search timelines such an event is a 260 px circle with no bubble, background, border or shadow (`mx_EventTile_inside_roundVideo` on the tile, which overrides skin bubble styles; the line is laid out as a photo, so the time and ticks sit on a pill over the circle's bottom right edge; a group sender's name is a small pill above it) with the duration and a muted mark on a pill at the bottom left. It loops muted while at least 30 % of it is on screen (IntersectionObserver) whatever Element's "autoplay videos" says (ordinary videos still follow it), but not with reduced motion, low bandwidth or Save-Data (then the first frame); a click plays it from the start with sound and a progress ring on its edge, a click again pauses, the end goes back to the loop; one round video plays with sound at a time and voice messages stop (`InsideRoundVideoBody.tsx`). Exports, the file panel and hidden media keep Element's video. |
| Calls joined from the incoming-call toast | The Element Call widget this app embeds (virtual, or served from the app's own origin) gets its OpenID token at once. A call accepted from the incoming-call toast asked for it before the stored permission was readable and showed "verify your identity"; while that dialog was open Element Call did not hand its leave over to lk-jwt-service, so a closed tab stayed in the call for an hour (`ElementWidgetDriver.isTrustedCallWidget`). |

Desktop `f985723`, Web K `13401b8`, Web A `6002824`). Only Telegram Desktop has the tap-to-switch
button: a press arms a 120 ms timer and a release before it (plus 0.2 s of samples) is a tap that
flips the app-wide `recordVideoMessages` setting
([history_view_voice_record_bar.cpp](https://github.com/telegramdesktop/tdesktop/blob/f985723b552b30fe1c17d377d57f44e61a15a8c4/Telegram/SourceFiles/history/view/controls/history_view_voice_record_bar.cpp),

hold records, release sends, sliding up by the lock's height locks, releasing outside the bar
cancels. Web K and Web A pick voice or video from the button's context menu and record on a click

## Build

`.github/workflows/inside-docker.yaml` runs, on `inside-v*` tags only, the unit and browser tests related to our changes (six shards, in parallel with the image build) (not the Storybook
visual suite: its baselines are Element's) and builds
`ghcr.io/balakirev/inside-element-web` from the stock `apps/web/Dockerfile`.
